# 对话式验收（Dialogue Acceptance）

## 适用 / 不适用

- 适用：学习型任务的产出（源码链路文档、机制说明、调研结论、排障报告）。
- 不适用：代码变更的验收（那类跑测试、看 diff、做 code review）。

## 铁律

1. **一轮只问 3–5 题**，等用户回答后再出下一轮。绝不把题库一次性倒完，绝不替用户回答。
2. **不奉承**。答得含糊就追问，不要用"基本正确""方向对了"糊弄过去。
3. **每个判定都要有依据**：文件:行号、日志原文、文档小节。没有依据的判定不许写。
4. **答错先反问，再纠正**。先问"那 X 和 Y 的区别是什么？"，让用户自己暴露边界，再给正确答案。
5. **区分三种缺陷**：不懂（⬜）/ 记混（🔴）/ 能懂但说不出（🟡）。三者补救方式不同，别混着记。
6. **同一盲区出现 2 次以上 → 升级为 must-fix**，必须回炉。
7. **"看过文档" ≠ "理解"**。只认用户自己组织的语言；照抄原句要追问。
8. **考纲来源是用户的每日任务清单，不是产出物**。不得用文档目录反推考纲，也不得自行扩大范围。清单缺失时先让用户贴原文，不要猜。
9. **先粗后细**。主干没通时，cache / 并发 / 数据结构这类细节题一律**降级为「暂缓」**，不判失败；等主干口述通过后再回头考。

## 流程（第 0 轮 + 5 轮）

| 轮次 | 名称 | 问什么 | 目的 |
|---|---|---|---|
| 0 | 定向 | 对齐用户每日任务清单里的原始描述；写清「本次覆盖的子段 / 不考的子段」；再读产出物确认版本 | 防跑偏 |
| 1 | 心智模型 | 一句话概括、阶段划分、为什么这样设计 | 查骨架 |
| 2 | 主干召回 | 按链路顺序随机抽点，问「输入 / 输出 / 失败分支」 | 查链条是否连贯 |
| 3 | 边界与反事实 | 单节点、零节点、重复 assume、Permit Wait、提前返回 | 查是否真读代码 |
| 4 | 失败与回滚 | 同步 vs 异步失败、退账位置、幂等、谁负责清理 | 查工程直觉 |
| 5 | 迁移 | 给新场景让用户预测行为 / 日志 / 指标 | 查能否脱离原文 |

第 1 轮不要超过 4 题；后续每轮 3–5 题。用户答完一轮就当场判分并给出下一轮，不要攒到最后。

## 考纲对齐（每次验收第一步）

先写下这三行，再出题：

```text
任务：<每日任务清单里的原文标题>
目标：<用户原话，不改写>
本次覆盖：<这条任务下的哪一段>（其余子段明确写「本轮不考」）
```

验收的是「任务目标是否达成」，不是「产出物是否自洽」。如果产出物只覆盖了任务的一部分，第 1 轮先问未覆盖部分，而不是顺着产出物的目录问。

## 判分标准

| 等级 | 定义 | 处理 |
|---|---|---|
| ✅ 掌握 | 术语准确，能说出输入、输出、失败分支，能举反例 | 通过 |
| 🟡 模糊 | 方向对，但缺关键限定，或把名词当解释 | 追问 1 次；仍模糊记盲区 |
| 🔴 误解 | 因果、顺序、责任方说反 | 立即纠正 + 给反例 + 记 must-fix |
| ⬜ 空白 | 答不出或只复述原句 | 记 must-fix + 给最小复读路径（精确到函数/行号） |

## 每轮输出格式

```markdown
### 第 N 轮：<主题>

| # | 问题 | 你的答案摘要 | 判定 | 依据 / 纠正 |
|---|---|---|---|---|

**本轮盲区**：<编号 + 一句话>
**下一轮**：<预告要考什么，不给答案>
```

## 断点恢复（用户说「继续验收」「接着上次」时）

新会话没有旧对话记忆，**以验收记录文件为唯一事实来源**。

1. 若用户指定了文件，直接用；否则在 `acceptance/` 下按修改时间找最新的 `.md`，取「进度快照」标记为进行中的那份。
2. 读三处：第 0 节（考纲原文）、盲区台账、进度快照。
3. 从快照里的「下次入口」继续：先补问快照里标「待答」的题，再进下一轮/下一步。
4. 不要重跑第 0 轮，不要重复考已标 `fixed` 的盲区。
5. 找不到记录或快照缺失，才走完整第 0 轮。

记录里必须始终保留「进度快照」：当前步、待答题、open 盲区、下次入口。验收中断时立即更新。

## 留档

- 每次验收写一个文件：`acceptance/<YYYY-MM-DD>-<task-slug>.md`
- 结构固定：
  1. 范围与版本（考什么、不考什么、依据的 commit / 文件行号）
  2. 轮次记录（照上面的表格）
  3. 盲区台账（编号 / 现象 / 正确表述 / 依据 / 复现次数 / 状态 open|fixed）
  4. 结论：通过 | 有条件通过 | 重做
  5. 复读清单（精确到文件:行号 + 一个自测问题）
- 用户回答后立即更新文件，不要等验收结束再补。

## 结论判定

- **通过**：主干全 ✅，边界 ≥ 2/3 ✅，失败回滚无 🔴。
- **有条件通过**：无 🔴，但有 ≤ 2 个 must-fix，且用户已用自己的话复述正确。
- **重做**：≥ 2 个 🔴，或主干链条断（说不出输入→输出→失败分支）。

## 反模式（出现即纠正自己）

- 出题只考名词解释（"什么是 assume？"）。
- 用户答错就长篇讲解，跳过追问。
- 一次问 8–10 题，把对话变成考试。
- 把文档写得好当成用户理解得好。
- 判"✅"却没有引用任何代码位置。
