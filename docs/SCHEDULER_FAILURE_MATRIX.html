1. 同步失败：7 种触发情况

全部发生在 schedulingCycle（schedule_one.go:138）内部。

#触发点位置status 码典型原因
1SchedulePod 返回 ErrNoNodesAvailable148-156UnschedulableAndUnresolvable快照里没有任何节点（schedulePod:419）
2SchedulePod 返回非 FitError158-161ErrorUpdateSnapshot 失败、PreFilter/Filter/Score 插件报 Error、selectHost 空列表
3SchedulePod 返回 FitError，无 PostFilter 插件169-172Unschedulable没有节点放得下，也无法抢占
4SchedulePod 返回 FitError，有 PostFilter 插件175-188Unschedulable走抢占（RunPostFilterPlugins），写 NominatedNodeName，下一轮再试
5assume 失败197-205Error典型是 cache 里已有该 Pod（重复 assume）
6RunReservePluginsReserve 失败208-228Rejected → Unschedulable，否则原样插件资源预留失败（如卷分配）
7RunPermitPlugins 失败（非 Wait 非 Success）231-253同上Permit 插件直接拒绝

要点：情况 6、7 已在 schedulingCycle 内部就地退账（RunReservePluginsUnreserve + Cache.ForgetPod，见 210-213、234-237），所以 FailureHandler 只负责重排队与记事件。Permit 返回 Wait 不算失败，真正阻塞在异步的 WaitOnPermit（framework.go:1525）。

2. 异步失败：3 个出口

全部发生在 bindingCycle（schedule_one.go:266）内部。

#触发点位置典型原因
1WaitOnPermit 失败279Permit 等待期间被插件 Reject 或插件侧超时报负（framework.go:1528-1536）
2RunPreBindPlugins 失败296绑定前准备失败，典型是卷挂载/参数准备
3sched.bind 失败320extender Bind 失败；RunBindPlugins 返回 Error，最典型是 Pods.Bind 的 HTTP 调用失败（default_binder.go:58）

SchedulingQueue.Done 在 PreBind 成功后（317）就调用，因为之后的失败只算 Error，不再判 Unschedulable。

6. 易踩的坑

  1. ForgetPod 失败只打日志（358-359），仍继续 FailureHandler，账可能没退干净，靠 cache TTL 兜底。
  2. Reserve 失败不会退两次：同步分支内联退账，FailureHandler 不碰 cache。
  3. assume 失败无需退账，因为 AssumePod 一开始就失败，cache 未变。
  4. Unreserve 撤销的是插件资源预留；assume 的撤销永远是 ForgetPod，层次不同。
  5. 成功路径不经过 handleBindingCycleError，RunPostBindPlugins（333）只在绑定成功时调用。
