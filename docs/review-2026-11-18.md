## 必须记住的五件事

### 1. `schedulePod` 的四个短路口

| 位置 | 条件 | 返回 | 后果 |
|---|---|---|---|
| `:414` | `UpdateSnapshot` 失败 | 原样 err | `AsStatus` → Error |
| `:419` | 快照 0 节点 | `ErrNoNodesAvailable` | `:153` 特判 → `UnschedulableAndUnresolvable`，**跳过抢占** |
| `:429` | 可行节点 0 个 | `*FitError` | 有 PostFilter 就抢占，最终 `Unschedulable` |
| `:438` | 可行节点恰好 1 个 | 直接返回 | **跳过 `prioritizeNodes` 与 `selectHost`** |

### 2. `ErrNoNodesAvailable` vs `FitError`

- `ErrNoNodesAvailable`：集群里**一个节点都没有** → `UnschedulableAndUnresolvable`，不抢占。
- `FitError`：有节点，但都放不下 → 默认 scheduler 有 `DefaultPreemption`（PostFilter），会跑抢占 → 最终 `Unschedulable`。
- `UnschedulableAndUnresolvable` = 「换什么集群状态都没救」；不只「无节点」，PreFilter/Filter 插件也能返回它。
- `Unschedulable` = 「这次不行，资源变了再试」。

### 3. `EvaluatedNodes` 只在成功路径有意义

- 单节点：`1 + diagnosis.NodeToStatus.Len()`。
- 多节点：`len(feasibleNodes) + diagnosis.NodeToStatus.Len()`。
- 0 可行节点：`schedulePod` 返回**零值** `ScheduleResult`，所以 `EvaluatedNodes = 0`；实际信息在 `FitError.NumAllNodes` 和 `FitError.Diagnosis`。
- 它只被 `bindingCycle` 的 V(2) 日志消费，不参与决策。

### 4. trace 只给耗时，FitError 才给原因

| 输出 | 级别 | 默认可见？ |
|---|---|---|
| `trace.LogIfLong(100ms)` | `klog.Info` = V0 | 总耗时 ≥100ms 时可见 |
| `-v=4` 下的 trace step | V4 绕过 step 阈值 | 所有 step 都打印 |
| `logger.V(3).Info("No PostFilter plugins...")` | V3 | 需要 `-v=3` |
| `FailedScheduling` 事件 | 事件，不走日志级别 | 可见（`kubectl describe pod`） |

### 5. 三段过滤的分工

| 阶段 | 作用范围 | 执行次数 | 核心动作 |
|---|---|---|---|
| PreFilter | Pod | 1 次 | 预计算、提前拒绝、用 `PreFilterResult.NodeNames` 缩小节点集 |
| Filter | 每个节点 | N 次（并行） | 硬条件筛选，失败原因写进 `Diagnosis` |
| PostFilter | Pod | 0 可行节点后 1 次 | 抢占、提名，本轮返回 `Unschedulable`，下轮再试 |

一句话：**PreFilter 做减法，Filter 做安检，PostFilter 做兜底。**

## 容易说错的两个细节

1. 抢占后的最终 Status 是 [`schedulingCycle:188`](https://github.com/kubernetes/kubernetes/blob/v1.32.0/pkg/scheduler/schedule_one.go#L188) 的 `NewStatus(Unschedulable).WithError(err)`。
   `WithPlugin(rejectorPlugin)` 是 [`RunPostFilterPlugins`](https://github.com/kubernetes/kubernetes/blob/v1.32.0/pkg/scheduler/framework/runtime/framework.go#L919) 内部（`:961`）的返回，不是最终返回。
2. `UnschedulableAndUnresolvable` 不只由「无节点」触发：
   - `ErrNoNodesAvailable` → `schedule_one.go:154`；
   - PreFilter 把节点过滤掉 → `framework.go:762`；
   - Filter 插件返回 → `framework.go:944`。
