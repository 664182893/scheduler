## 必须记住的四件事

### 1. 账记上了才要退

| 出口 | 退账 | 动作 |
|---|---|---|
| `SchedulePod` 失败 | 无 | `assume` 还没执行 |
| `assume` 失败 | 无 | 账还没记上；再 `ForgetPod` 会报 `wasn't assumed` |
| `Reserve` 失败 | 有 | `RunReservePluginsUnreserve` + `Cache.ForgetPod` |
| `Permit` 失败（非 Wait） | 有 | 同上 |
| `Permit` 返回 Wait | 不退 | Wait 不是失败，进 bindingCycle 等 |

### 2. `ForgetPod` 的守卫

- 只有 `assumedPods` 里的 Pod 才能退；
- 否则返回 `wasn't assumed so cannot be forgotten`；
- 真正删账在 `removePod`：`NodeInfo.RemovePod` + `delete podStates` + `delete assumedPods`。

### 3. 框架函数 vs 调用方

- `RunReservePluginsReserve` 只负责遍历插件、返回 Status，**不做退账**；
- 退账在调用方 `schedulingCycle` 的失败分支；
- `RunReservePluginsUnreserve` **逆序**调用 `Unreserve`。

### 4. `DeepCopy` 防的是什么

- `podInfo.Pod` 来自队列，队列对象来自 informer；
- `assume` 会写 `Spec.NodeName`；
- 不复制 → 污染 informer 缓存 → `handleSchedulingFailure` 看到 `cachedPod.Spec.NodeName != ""` → 认为已绑定 → 跳过重新入队 → Pod 永久 Pending；
- 复制后 → 只改副本 → 失败时用 `cachedPod.DeepCopy()` 重建并重新入队。
